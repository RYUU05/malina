# Malina App

`Malina` — небольшое Flutter-приложение с локальным сценарием заказа еды и бьюти-услуг.  
Проект не использует backend: авторизация, корзина и часть пользовательского состояния сохраняются локально через `SharedPreferences`.

README ниже написан как короткий гид по проекту: что уже реализовано, как запустить приложение, где искать основную логику и какие ограничения сейчас есть.

## Что умеет приложение

- Авторизация по email и паролю.
- Проверка формата email на экране входа.
- Блокировка после трех неудачных попыток входа для конкретного пользователя.
- Главный экран с категориями и переходом в QR-сканер.
- Корзина с разделением по категориям `Еда` и `Бьюти`.
- Добавление товаров вручную через отдельный экран.
- Заполнение формы товара через QR-сканирование.
- Локальное сохранение корзины для текущего пользователя.
- Экран профиля с выходом из аккаунта и удалением локальных данных пользователя.
- Экран избранного с загрузкой, отображением и удалением сохраненных элементов.

## Что важно знать сразу

- Это локальный demo-проект, а не production-приложение.
- Реального API здесь нет.
- Данные живут на устройстве в `SharedPreferences`.
- После перезапуска приложения сохраненные локально данные остаются.
- Корзина хранится отдельно для каждого пользователя.

## Тестовые данные для входа

Для входа можно использовать:

- любой email в корректном формате, например `user@example.com`
- пароль `admin123`

Поведение авторизации:

- если пароль неверный, увеличивается счетчик неудачных попыток
- после трех неверных попыток пользователь переводится в состояние блокировки
- при успешном входе счетчик ошибок для этого пользователя сбрасывается

## Основные сценарии в приложении

### 1. Вход

После запуска приложение открывает экран логина.  
Если пользователь уже был авторизован ранее, роутер пропускает экран входа и отправляет его сразу на основной экран.

### 2. Главный экран

На главном экране есть:

- поле поиска
- баннер для перехода в QR-сканер
- карточки категорий
- блок "Скоро в Malina"

### 3. Навигация

После входа появляется нижняя навигация:

- `Лента`
- `Избранное`
- центральная кнопка `QR`
- `Профиль`
- `Корзина`

Для корзины используется отдельное всплывающее меню выбора категории.

### 4. Добавление товара

Товар можно добавить двумя способами:

- вручную через экран `Добавить`
- через QR-сканирование

Если QR содержит строку в формате:

```text
food/подкатегория/название/цена/описание
```

или

```text
beauty/подкатегория/название/цена/описание
```

то форма заполнится автоматически.

### 5. Корзина

В корзине можно:

- смотреть товары по категориям
- менять количество
- удалять отдельные позиции
- очистить всю корзину

Сохранение сделано с небольшим debounce, чтобы не писать в локальное хранилище на каждый клик мгновенно.

### 6. Профиль

На экране профиля доступны:

- просмотр текущего логина
- выход из аккаунта
- удаление аккаунта с очисткой локальных данных

### 7. Избранное

В проекте есть отдельная фича избранного с `BLoC` и репозиторием.  
Сейчас экран умеет:

- загружать локально сохраненные элементы
- показывать empty/error state
- удалять элемент из избранного

Сценарий добавления в избранное из каталога пока не подключен к UI.

## Архитектура проекта

Проект организован по feature-based структуре.

### Core

- `lib/core/di` — регистрация зависимостей через `GetIt`
- `lib/core/router` — конфигурация `GoRouter`

### Features

- `lib/features/auth` — логика авторизации, события/состояния и экран входа
- `lib/features/cart` — модели корзины, репозиторий, BLoC и экраны корзины
- `lib/features/favorites` — экран избранного, BLoC, модель и локальный репозиторий
- `lib/features/home` — главный экран
- `lib/features/profile` — экран профиля
- `lib/features/qr` — QR-сканер
- `lib/features/shell` — общий shell с нижней навигацией

### Слои, которые используются в проекте

- `presentation` — экраны и виджеты
- `bloc` — состояние и события
- `data` — репозитории и доступ к локальному хранилищу
- `domain` — модели данных

Не у каждой фичи есть полный набор слоев.  
Например, `home` и `profile` сейчас в основном UI-ориентированные и не требуют отдельного `data/domain` слоя.

## Локальное хранение

Проект использует `SharedPreferences` для нескольких сценариев:

- хранение текущего пользователя
- хранение числа неудачных попыток входа
- хранение корзины по username
- хранение избранного

Это удобно для demo-проекта, но для production-версии такие данные логичнее вынести в более явный слой хранения или в backend.

## Как запустить проект

### Требования

- Flutter SDK
- Dart SDK
- устройство, эмулятор или desktop/web target для запуска

### Быстрый старт

```bash
flutter pub get
flutter run
```

### Если менялись модели Freezed или JSON-сериализация

Сгенерированные файлы уже лежат в репозитории, поэтому для обычного запуска команда ниже не обязательна.  
Но если вы изменяли модели в `domain`, нужно обновить генерацию:

```bash
dart run build_runner build --delete-conflicting-outputs
```

## Полезные команды

Проверка проекта:

```bash
flutter analyze
flutter test
```

Запуск интеграционного теста:

```bash
flutter test integration_test/app_test.dart -d macos
```

Если подключено несколько устройств, Flutter попросит явно указать target через `-d`.

## Тесты

Сейчас в проекте есть:

- unit-тесты для `AuthRepository`
- widget-тесты для `LoginPage`
- базовый smoke integration test на запуск приложения

Покрытие пока небольшое, но уже проверяет критичный стартовый сценарий:

- успешную и неуспешную авторизацию на уровне репозитория
- валидацию формы логина
- запуск приложения и отображение экрана входа

## Ограничения текущей версии

- нет backend и сетевого слоя
- пароль зашит в коде
- нет полноценного сценария добавления в избранное из UI
- поиск на главном экране пока визуальный
- нет полноценного набора интеграционных тестов пользовательских сценариев

## Что можно развивать дальше

- подключить реальный backend для авторизации и каталога
- выделить use case слой там, где логика начнет усложняться
- добавить редактирование профиля
- связать каталог с избранным
- покрыть тестами корзину, роутинг и сценарии авторизации через BLoC
- вынести константы, тексты и форматирование валюты в отдельные utility/service слои

## Коротко по смыслу проекта

Это аккуратный локальный Flutter-проект, в котором можно посмотреть:

- feature-структуру
- BLoC-подход для состояния
- `GoRouter` с auth-based redirect
- хранение локальных данных
